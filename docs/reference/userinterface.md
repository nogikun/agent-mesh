## 1. 背景

mesh CLI をスキルに組み込むにあたり、「もっと人間に優しいインターフェースにすべきか」「Python の CLI ライブラリ（Typer、Rich など）を使うべきか」を検討した。結論は次のとおり。

- CLI のライブラリを替える必要も、Python で書き直す必要もない。
- 直すべきなのは「出力の見せ方」と「起動の手間」である。

## 2. 主な利用者はエージェント

スキルに組み込んだとき、mesh を一番よく呼ぶのは人間ではなく Claude と Codex である。エージェントにとって扱いやすいのは次の3つ。

- 毎回同じ形の JSON が返る
- 終了コードで成否が分かる
- 対話の入力を求めない

IF仕様 §3 でも「エージェントは `--json` を使い、人向けの表示を解析しない」と決めている。現在の「常に JSON を出す」はエージェント向けとしては正しい。ここを人間向けの色付き表示に変えると、かえってスキルが壊れやすくなる。

## 3. 出力を2つの層に分ける

`gh` や `kubectl` と同じやり方をとる。

| 呼ばれ方 | 出力 |
|---|---|
| 端末で直接打ったとき（stdout が TTY） | 人が読みやすい短い表示 |
| `--json` を付けたとき、またはパイプ経由で呼ばれたとき | 現在の JSON のまま |

端末での表示の例：

```text
✓ codex-dev に送信しました  requestId: req_c59a…
  結果は mesh inbox で確認できます
```

エージェントは `--json` を付けて呼ぶので、人間向けの表示を変えてもスキルには影響しない。SKILL.md は `--json` を付ける前提に書き直す。

## 4. 手間を減らす改善

実際に触ってつまずいたのは、表示よりも手順の多さだった。

| 今の手間 | 改善案 | 状態 |
|---|---|---|
| ターミナル2つで Runtime を起動する | `mesh up` で2つを裏で起動し、`mesh down` で止める | 未実装 |
| 毎回 `export MESH_CONFIG=...` が要る | `~/.config/agent-mesh/` の設定を既定で使う | 未実装 |
| `requestId` をコピーして `task get` に貼る | `mesh task get`（引数なし）で直前の依頼を見る | 未実装 |
| 結果が届くまで `inbox` を何度も見る | 人間用に `mesh send --wait`（届くまで待って結果を表示） | 未実装 |
| ポート使用中などのエラーが分かりにくい | 原因と次にすることを1行で出す | ポート使用中は実装済み（`CONFLICT` と確認方法を表示） |

`mesh send --wait` は人間が端末で使うためのものである。エージェントには、完了待ちで LLM を繰り返し動かさない方針（R04）のとおり、`--wait` を使わせない。

## 5. ライブラリの選択

| 案 | 判断 | 理由 |
|---|---|---|
| Python（Typer、Rich）で CLI を書き直す | 不採用 | Runtime 本体が TypeScript なので、言語が2つに分かれ、配布も面倒になる |
| Node の CLI ライブラリ（`commander`、`citty`、表示に `picocolors`、対話に `@clack/prompts`） | 必要になったら | Python と同等のものが Node にもある |
| Node 標準の `parseArgs` のまま | **採用** | 今の CLI は依存ゼロで、コマンド数も少ない。4章の改善は標準機能で足りる |

サブコマンドが増えて手に負えなくなったら、`commander` を足すくらいでよい。依存を足す場合は、スキルに同梱するコピー（`tools/mesh/`）に依存を入れる方法も合わせて決める（スキル配布設計 4.2 では、実行時の依存がないことを前提にしている）。

## 6. スキルとの関係

スキル側には手順の案内だけを書き、処理はすべて mesh CLI に任せる（IF仕様 §2、「Skill は操作ガイドでありビジネスロジックを複製しない」）。そうしておけば、Claude Code と Codex の両方から同じスキルを使える。

## 7. 進める順番

1. 端末なら人間向けの表示、`--json` やパイプなら JSON に切り替える。
2. `mesh up` / `mesh down` と、既定の設定ファイルを読む仕組みを足す。
3. `mesh send --wait` と、引数なしの `mesh task get` を足す。
4. SKILL.md を `--json` 前提に書き直し、Claude Code と Codex の両方で読み込めるか確かめる。
