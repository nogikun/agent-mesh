## 1. 利用者と用語

利用者＝人間の管理者、依頼元エージェント、受信先エージェント。すべてのCLIエージェントは送信者にも受信者にもなれる。Nodeはホスト上のRuntime、Agentは論理的な実行主体、Sessionはプロバイダー会話、Taskは依頼単位。ConnectorはMuse等から利用する入口であり、推論起動機能とは異なる。

モード：S=Skill+CLI、R=Skill+Runtime、C=Connector（別途バックエンド必要）、RC=R+C。RにはSの機能が含まれる。条件付き機能は検証に合格するまで無効。以下の機能は設計目標で、現状の実装済み機能ではない。

## 3. 機能仕様

### F01 環境診断

入力：OS、インストール済みCLI、選択モジュール。出力：バージョン、機能capabilities、認証モード確認結果、欠けた依存、既存設定競合。`mesh doctor --json` は秘密を出さない。未認証は正規ログイン手順を案内し、APIキーで自動代替しない。実行にサブスク条件がある場合は未確認表示。

### F02 選択インストール

初回はSのみ。`mesh setup --runtime` 等でRを追加し、Connectorは独立したsetup。プラン表示・必要権限・外部公開有無を提示、承認後に適用。既存設定をバックアップし変更点だけマージ。何度も実行しても重複サービスを作らない。更新は版固定、ロールバック可能。失敗は未適用/部分適用を区別し復旧手順を返す。Skill追加だけで常駐や公開を勝手に有効化しない。

### F03 エージェント登録・発見

ユーザー指定endpoint、または承認済みcontactからAgent Cardを取得。名前、ID、能力、A2A版、認証要求、利用可能なskillsを提示。名前衝突は一意IDで解決。未知のAgent Cardを信頼して自動実行・credential送付しない。peerを無効化すると新規依頼と通知受信を拒否。

### F04 タスク送信

必須：宛先、目的、依頼内容。任意：context、添付、deadline、親task、結果到着時の扱い。既定は非同期。依頼が受理されTaskまたは直接Messageが返ったら結果を返す。依頼元は別作業に進める。Task IDを表示し、通信異常で受理が不明なら `OUTCOME_UNKNOWN`。同じ依頼の無条件再送は行わない。Sでは自動wakeは発生しない。

### F05 状態・結果取得

ローカルrequestId/taskIdまたはpeerとremoteTaskIdを入力し、実行状態、結果、成果物メタデータを返す。キャッシュの場合は更新時刻と明示する。未完了・承認待ち・失敗を成功扱いしない。添付ダウンロードは明示指定、checksum・サイズ検査。別エージェントの非許可タスクは参照不可。

### F06 受信・実行

受信ノードは認証・認可・入力・冪等性を確認し、永続化後にACK。設定されたworkspace/profileでのみ実行。許可待ちならタスク状態を更新して利用者に知らせる。同時実行上限に達した場合はキューへ。終了結果を保存して状態を更新、通知を登録。起動できない場合は明示したエラーを返す。

### F07 イベント受信・通知

A2A Push/SSEの能力に応じて選択。受信結果はinboxへ永続化し、重複・古い通知を除外。非LLMの状態照合は例外的な補助。通知が取得不能な相手には自動通知対応と表示しない。結果が届いた時点で依頼元が終了していてもRは保持。既定では人への通知/参照可能状態にする（autoResume opt-in）。

### F08 セッション再開

既存のRuntime管理セッションと結果を関連付ける。人が自動再開を許可した場合、IDLEかつ正しいworkspaceのセッションを同じprovider session IDで再開。実行中はキューに保持し、ターン境界の検知後に処理。管理外セッションや状態不明では再開せず確認を促す。起動障害・利用上限・認証失効は停止して知らせる。完了待ちのためのLLM再推論は禁止。複数イベントのまとめ投入は許可されたものだけ。

### F09 並列依頼

一つの依頼元から複数エージェントへ個別requestIdで送信。依頼元と各受信先は独立に進行。結果を順不同で収集。グループ集約は補助機能であり、全員完了を待たなければ次に進めない構成にしない。一部失敗を識別し、他タスクを自動取消しない。同一セッションで同時推論を行わない。

### F10 質問・承認・取消

A2AのINPUT_REQUIRED/AUTH_REQUIREDに応じ、必要な入力だけを提示。返信はtaskId/contextIdに関連付け、別依頼として誤送しない。人の承認は対象・範囲・期限に結び付ける。認証情報をエージェント間メッセージで渡さない。取消はbest effortで、既に発生した副作用は取り消せない場合がある。terminalタスクは新規IDで再依頼。

### F11 LAN/Tailscale

利用者が既存TailscaleまたはLANを選択。接続先と公開範囲を表示。Tailscale Serve/privateを優先、ACLを利用。Tailscale自体の登録や管理者承認を無断で行わない。NAT越えのための公開トンネルは既定で無効。疎通不能時は原因と設定箇所を表示。通信の可用性と認可は別に扱う。

### F12 Muse Custom Connector

Museに利用可能なエージェント一覧、依頼送信、状態取得、結果取得、取消を提供する。公開接続先と安全な認証、利用者による承認が必要。まず個人用接続ガイドとツール説明を配布し、実際のMuse UIでのカスタム作成フローを検証する。リモートMCP/API対応の具体方式は確定前。公式ディレクトリ公開はMeta審査後にのみ可能。詳しくはIF仕様7章。

### F13 Museへの自動起動（調査のみ）

メール受信・Connector利用は、任意の既存Museセッションが外部イベントで起動することを意味しない。公式の受信トリガー・アカウント条件・利用者承認・重複抑止が確認できた場合だけ実装する。確認できない場合は手動で結果参照する機能に限定。非公開API・画面操作による強制起動は採用しない。

### F14 監査・障害復旧

Runtime起動時に未配送/未実行を復元し、状態不明の実行は人による照合を求める。管理者は `mesh inbox` / `mesh status` から進捗、失敗理由、保留を確認。ログはtraceId、action、actor、outcome中心。期限・保存容量を設定し、データ削除と権限失効を提供する。

### F15 権限制御

管理者はエージェント別にworkspace、送信可能peer、許可操作、autoResume、同時実行数、最大依頼深度・件数・期限を設定。未知の宛先と任意シェルコマンドを既定拒否。親の権限を超える委譲を拒否。緊急停止で新規起動・配送を停止し、現在の実行に対する停止要求を発行。外部サービスの利用枠を回避する目的の自動アカウント切替は対象外。

### F16 CAO実行バックエンド

既存CAO利用者が任意に選ぶ。CAOの正式control-planeでlaunch/send/status、イベントプラグインで完了を受ける。A2Aの通信ロジックは変更せず、Directと同じPortを実装。CAO停止/版不整合時は明示エラー、既存タスクを黙って別backendに再実行しない。

## 4. 代表ユースケース

### UC01 Claude → Codex（同一ホストまたはTailscale、R）

事前：CLI正規ログイン、相互peer登録、Runtime稼働、workspace許可、autoResumeの明示許可。ClaudeがCodexにレビューを依頼しIDを受け取る。Claudeは別の実装を続ける。Codexが終了しRuntimeがイベントを永続化する。Claudeが別作業中なら待機し、安全なターン境界で同じセッションへ結果を投入。終了：結果が記録され、別作業を中断せず、待機用推論0回。逆方向も同様。

### UC02 Skill単体で既存A2Aへ依頼（S）

事前：a2aバイナリと既存接続先。利用者がSkillを通じ送信。IDを受領し別作業。後で `mesh task get` により結果取得。ローカル常駐プロセスなし。自動wakeが必要ならRuntime導入を案内。

### UC03 Muse → Claude/Codex（RC）

事前：公式に許容された個別Connector接続、認証、scope、ユーザー承認。Museがエージェントを選択し作業依頼。ConnectorはタスクIDを返し、結果を後で参照可能にする。自動でMuseが起きるとは約束しない。取消/認可失効時は以後の接続を拒否。外部コネクターは承認済みworkspaceに限定。

### UC04 ネットワーク障害・重複通知（R）

Codexが終了したが通知配送が失敗。Outboxに保留し再接続後に送信。Claude側は同一eventの重複を無視。セッションが起動済みか不明ならUNCERTAINとして停止。人による確認後に処理を再開。

## 5. 受入テスト計画

| ID | シナリオ | 合格条件 |
|---|---|---|
| AT01 | CLI未導入・未認証・異版 | 明確な診断、秘密出力なし、望まないAPI課金モードで起動しない |
| AT02 | S→R→Connector追加→R削除 | 選択した部品のみ有効、既存設定保持、Sに戻せる |
| AT03 | 正常card・未知peer・同名agent | IDで特定、未知の自動実行拒否 |
| AT04 | 10分かかる依頼の非同期送信 | 完了前に受領ID、依頼元が別作業可能、直接Messageも扱える |
| AT05 | 完了/失敗/中断/未存在 | 正しい状態、結果と更新時刻、権限外参照拒否 |
| AT06 | 両CLIへ双方向実行 | 正規CLIログインで両方向成功、同一冪等キーは1タスク |
| AT07 | duplicate/reorder/SSE切断 | 結果保持、terminal巻戻しなし、LLMポーリング0 |
| AT08 | idle/busy/unknown/autoResume off | idle+許可時のみ再開、busyはキュー、unknownは保留、二重起動なし |
| AT09 | 2宛先同時依頼・片方失敗 | 独立進行、結果の対応付け、1失敗で他を止めない |
| AT10 | 入力待ち・取消・期限 | 正しいtaskへ回答、承認遵守、確定状態を表示 |
| AT11 | 別LANの2ホスト/Tailscale | tailnet限定の相互疎通、無断公開なし |
| AT12 | Muse個別接続・送信・取得・失効 | 実アカウントで正規手順成功、scope制御、失効後拒否。失敗なら未対応表示 |
| AT13 | 公式Muse wake調査 | 公式資料と実機証跡が揃うまで提供しない（リリース必須ではない） |
| AT14 | kill/restart、commit前後障害 | 受領済みタスク復旧、既存副作用の不明状態を自動再実行しない |
| AT15 | 注入、権限外パス、ループ、上限 | 全て拒否/承認待ち、監査記録 |
| AT16 | CAOイベント、停止、版不整合 | Directと同じ機能契約、切替で二重起動しない |

## 6. リリース範囲

G1=F01–F05のS、F15基本。G2=F06–F11,F14,F15のR、F08の両CLI契約試験合格必須。G3=F16、G4=F12、F13は独立の実現性調査。G5=運用・配布仕上げ。各段階で実装済み機能と実験機能を `mesh doctor` に反映し、未確認のプロバイダー能力を宣伝しない。
